# Goal

Implement a total deterministic Werewolf reducer whose authorization and simultaneous resolution
are inspectable independently of networking and presentation. Assumes W-D1..18 in
[00-decisions-and-phases.md](00-decisions-and-phases.md) are accepted.

## Current state

The skeleton has no compiled domain types. Existing contracts already provide `Input`, `Ctx`,
`Effect`, `SeatId`, `SeatRoster`, `DetRng`, `LogicalTime`, `RuleError` and `MatchOutcome`.
There is no `is_terminal` hook: `Effect::EndMatch` is the shell's terminal authority.

## Proposed architecture

```text
rules/config.rs      validated preset, vote mode, durations, max_rounds
rules/role.rs        Role, Alignment, role distribution
rules/state.rs       private State/RawState, Phase, NightChoices, Ballot, resources
rules/command.rs     Command, NightAction, validated command witnesses
rules/resolution.rs  pure night/vote/death/retaliation/outcome decisions
rules/scopes.rs      absolute chat and voice-membership values
rules/projection.rs  View, knowledge types, project, describe
rules/event.rs       canonical Event, distinct ViewEvent, view_event
rules/mod.rs         GameRules, create, validate/commit dispatch, RULES_VERSION/HASH
rules/secret.rs      SecretModel (cfg(test) or testkit)
simulation.rs        verification policy/module (outside hashed rules subtree)
lib.rs               GameModule, validated metadata and capabilities
```

Public types document their purpose and invariant ids. Use ordinary structs/enums; no generic
typestate framework. Rules never import simulation, presentation or package configuration.

### State and construction barriers

| Type | Meaning and validation boundary |
|---|---|
| Config | Named preset; durations 1s..10min; max_rounds 1..100; vote mode. Raw serde DTO → TryFrom; no constructor bypass via Default |
| State | Ordered seat list, exact role map, alive set, revealed map, phase, round, timer identity/deadline, connection/absence flags, choices, votes, potion inventory, Doctor history, Seer result history, bounded last-resolution facts |
| Phase | Night, Dawn, Day, Vote, Dusk carrying round/window facts; Ended carrying result. No rule-owned Lobby or Ready state; creation starts Night 1 |
| NightChoices | Per-seat `Pending` or `Submitted(action/pass)`; only eligible living roles get a slot; one choice per Night |
| Ballot | Target(SeatId) or Abstain; no ballot is distinct from explicit abstention for own UI but both resolve as abstain |
| NightAction | WolfTarget, Investigate, Protect, WitchHeal, WitchPoison, HunterMark, Pass; raw SeatId targets validated against this state |
| Command | Night(action), Vote(ballot), Unvote. No debug, chat, voice, host, Ready or speech-token commands |
| ValidatedAction | Private witness tied to actor, phase/window and target; created and consumed inside the same apply call, never serializable or cacheable |
| Resolution | An immutable proposed death set, resource/result updates, ordered canonical events and optional MatchOutcome; compute before mutating State |

State decoding validates: seat uniqueness/count; role counts match preset; alive/revealed partition;
keys and targets belong to roster; phase/round/timer coherence; choices authorized by role and
window; potion use/history bounded; votes refer to allowed seats; terminal result covers every
seat once with contiguous ranks. Validate **structural** admissibility, not historical reachability:
semantic properties use states generated by create plus legal prefixes. Private fields alone do
not prove these coupled invariants. Derive Serialize, validate Deserialize through a raw DTO.

Do not use an independent player-index identity or assume SeatId is 0..n. Role assignment sorts
the supplied SeatIds. No floating point, HashMap, clock reads, OS randomness or panicking indexing.

## Decisions: the phase and input table

| Current phase / trigger | Decision | Next phase |
|---|---|---|
| create | Validate fully, shuffle role multiset, emit server-only RolesAssigned, initial public phase and scope values | Night 1 |
| Night / valid private action | Record one immutable choice; consume potion if selected; emit private submission | Night, same deadline/scopes |
| Night / due timer | Default pending choices, resolve complete simultaneous batch, then check victory | Dawn or Ended |
| Dawn / due timer | No further night mutation; keep public deaths/results | Day |
| Day / due timer | Open voting with empty ballots | Vote |
| Vote / Vote or Unvote | Replace/remove own public ballot; repeat identical vote/unvote-with-no-ballot rejects IllegalMove | Vote, same deadline |
| Vote / due timer | Resolve ballots, elimination and Hunter retaliation, then check victory | Dusk or Ended |
| Dusk / due timer | If round limit reached, stalemate draw; else clear round choices/mark/votes | Night n+1 or Ended |
| Any playing phase / Seat | Known seat only; Disconnected/WentIdle prevent new input until Reconnected/BecameActive; accepted choices survive. Abandoned/Vacated is permanent absence | Same phase/deadline |
| Any playing phase / Occupied or OccupantChanged | Reject Unsupported (no rebinding of a knowledge-bearing seat) | Unchanged |
| Any playing phase / Admin(Cancel) | Abort with all seats rank 0, emit EndMatch once | Ended |
| Admin(Pause, Resume, ForceEnd) | Reject Unsupported | Unchanged |
| Ended / any input | Reject MatchOver; no effects/events | Ended |

Player validation order: terminal → seat membership → public phase/time window → alive/available
actor → actor's role/unused slot or resource → target eligibility. Return generic existing codes;
no hidden target role, action count, or other actor's resource in error details. Wolf targets may
exclude wolves because wolves already know teammates; Seer/Doctor/Witch targets cannot be filtered
by a secret result. A missing/invalid Seat viewer is public, never Audit or dead.

### Timers and totality

- Store current TimerId and absolute ends_at. Use a fresh monotonically allocated u16 timer id per
  phase entry: at most 5 × 100 ids, validated by max_rounds; no wrapping or reuse within a match.
- Matching timer is effective only when `ctx.now >= ends_at`. Early/unknown/duplicate/stale timers
  return accepted empty outcome while playing. This does not mean they are rejected: I-7 advances
  for every Ok, including no-ops. A duplicate old id cannot close a newer phase.
- Player windows are half-open: `ctx.now < ends_at`. At the deadline reject WrongPhase until the
  timer arrives; never resolve a private phase early as a side effect of a player's late command.
- Before commit, use checked deadline arithmetic. If `ctx.now + next_duration` cannot be represented,
  reject with a public-safe error and unchanged state; do not silently saturate into a zero-progress
  timer. Test maximum LogicalTime explicitly; upstream arithmetic proofs do not prove this policy.
- Each transition cancels the old timer and, unless ending, arms the new one. Emit absolute scopes
  once per phase/death change, never per secret action. Public deadlines depend on config/phase only.

### Independent resolution definition

Freeze roles, living seats and submitted choices at closure. Missing choices are passes.

1. Count wolf targets; unique positive maximum attacks one seat, otherwise no attack.
2. Cancel that attack if either Doctor protection or Witch heal names it. Healing/protection does
   not expose whether an attack existed; acknowledge own choice only, not "successful save".
3. Add Witch poison target independently; protection/heal cannot cancel poison.
4. Union deaths so duplicate causes kill once. Choices from actors in that set still take effect.
5. If Hunter is in the death set, add its precommitted target if living and not already dead;
   one Hunter exists per preset, so no recursive unbounded chain. No action after full dead vision.
6. Produce public deaths in ascending SeatId with role but **without cause**; authorized/audit
   details use distinct event variants. Seer result uses frozen alignment, delivered at Dawn.
   Emit a resolution record for every submitted protection/heal, effective or not; its owner's
   acknowledgement must not reveal attack existence through a conditional event.
7. Check empty-alive draw, zero-wolf village win, then wolf parity. Return one outcome for the
   full roster, including dead seats; winning alignment rank 0, losing alignment rank 1.

Vote resolver: derive tallies from ballots, not a mutable cached tally. Ignore abstention as a
candidate. Require unique highest positive count; AbsoluteMajority additionally requires
`count > living_count / 2`. Eliminate or no-op; then steps 5–7 above. All-abstain never chooses a
seat by accident. Decide a stable canonical event order: phase change (when continuing), private
results, sorted death facts, public aggregate result, Ended last when terminal. Snapshot the
post-transition state for all events from that input; test authorization changes within that batch.

### Projections, legal commands and scopes

See [02-secrecy-and-projections.md](02-secrecy-and-projections.md). `legal_commands` is Enumerated
for active roles and voters, None otherwise; stable enum-discriminant/SeatId order, no duplicates.
Build view affordances from the same game-local eligibility predicates; `apply` must never call
legal_commands as its authority. Vote excludes self; Hunter/Seer exclude self; Doctor/Witch may
target self. Night wolves exclude teammates; all targeting checks living status at submission.

Chat values in fixed channel order table, wolves, dead:

| Phase | Table speak/listen | Wolves speak/listen | Dead speak/listen |
|---|---|---|---|
| Night | none / none | living wolves / living wolves + dead | dead / dead |
| Dawn, Vote, Dusk | none / all seats | none / none | dead / dead |
| Day | living / all seats | none / none | dead / dead |
| Ended | all seats / all seats | none / none | none / none |

Participants expresses seats only. Outside spectator chat is not inferred as Everyone; attach and
read-only spectator delivery require Phase-7 design. Voice Phase-3 values exercise matching room
membership for wolves/dead/table only; dead-listen-only access to wolf media is **not representable**
and is explicitly deferred to the generic voice permission design.

## Invariants

| ID | Invariant / owner |
|---|---|
| W-I1 | Validated state maintains fixed role/seat binding; create owns RNG assignment |
| W-I2 | apply error preserves complete canonical bytes; private witnesses cover authorization, commit has no fallible checks |
| W-I3 | Phase changes occur only on due active timers or explicit terminal admin input |
| W-I4 | Every night choice is authorized, submitted at most once, and resolved from one frozen batch |
| W-I5 | Alive set only shrinks; a death/reveal/retaliation happens once |
| W-I6 | Same seed and ordered timed inputs produce identical state/events/effects; I-7 belongs to the driver |
| W-I7 | Only projections and redacted events reach client-shaped outputs; no private counts/metadata/scopes |
| W-I8 | EndMatch emitted once; with delivered timers and bounded input traffic max_rounds reaches a terminal outcome |

## Expected file changes

Files in the module map, `games/werewolf/{Cargo.toml,game.toml,build.rs}`, and tests
`{config,assignment,phases,night,voting,conformance}.rs`. No platform code. New dependencies use
workspace aliases already permitted by `deps.toml` (thiserror, proptest, blake3 as needed).

## Implementation steps

Follow W1–W5 in [05-pr-sequence.md](05-pr-sequence.md). W3/W4 expose pure helper kernels with
tests while the public GameRules adapter remains explicitly disabled; W5 activates a complete
reducer only after projection and event contracts from W6/W7 are ready. Do not ship a partially
working GameRules with TODO arms or unredacted View aliases.

## Acceptance criteria

- [ ] All input variants and all role/potion/target combinations have defined results.
- [ ] Checked reconstruction and round trips preserve state invariants; no panic shortcuts.
- [ ] Due/stale timers, all-pass liveness, Hunter plus simultaneous poison, and parity tested.
- [ ] Public adapter cannot be enabled until W5 + W6 + W7 coverage passes.

## Residual risks

StateSizeClass must follow actual encoded size, especially retained Seer results and last-resolution
facts. Fixed Night/Day/Vote deadlines provide bounded phase progress only when the shell delivers
them. Full-vision dead participants cannot be prevented from talking outside Tabula.
