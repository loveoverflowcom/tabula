# Renderer and embedding spike — issue #60

This is an isolated experiment for [issue #60](https://github.com/loveoverflowcom/tabula/issues/60).
The separate-document Macroquad baseline, same-origin Macroquad iframe, and direct PixiJS
canvas answer two independent questions: how a runtime is embedded, and which renderer executes
the permitted view. No production route or match ownership moves into this tool.

See [RUNNING.md](RUNNING.md) for build/stage/run commands and the runtime harness. The decision
and measured limits are recorded in [the RFC](../../docs/rfcs/issue-60-renderer-embedding.md),
[ADR-0029](../../docs/adr/0029-renderer-embedding-spike.md) and the issue #60 verification report.

## Authority and contract

`xtask/examples/embedding_fixture.rs` owns the actual rules, permitted projection, presenter,
camera, animation and input-to-intent logic. It emits `fixtures/render-contract.json` and the
small checkpoint corpus. Command and frame field lists are generated by Rust. `boundary.mjs`
uses those exact field lists, rejects additional fields recursively, validates numeric ranges,
asset references and balanced typed scopes, then clones accepted views to prevent later caller
mutation. Canonical `State`, seeds, bags, secrets and arbitrary game payloads have no accepted
field in this boundary. This is experiment schema version 1, not a new production protocol.

The native Rust stdin fixture authority is reached through a loopback HTTP shim for live input.
That includes subprocess, HTTP and serialized RenderList cost. It is not a deployable WASM
interop design or a recommendation to serialize a full RenderList per production frame.
JavaScript normalizes DOM input and draws the returned view; it never duplicates legal moves,
scoring, state transitions, hidden information, or match networking. There is no match socket.

`adapter.mjs` exports `mount(options)` synchronously with an async `ready` promise. The returned
controller exposes `set_view`, `resize`, `set_preferences`, `set_theme`, `suspend`, `resume`,
`dispose` and `snapshot`. A view carries `schema_version`, `session_id`, `generation`, `revision`
and `frame`. A mount accepts only its own identity and strictly increasing view revision.
`on_input` includes identity and the current projected revision; the host serializes requests
and Rust rejects stale identities and revisions again.

`bridge.mjs` gives the iframe one listener and an exact-origin, exact-source, identity-scoped,
monotonic envelope. It uses channel `tabula-renderer-spike`, protocol 1, and exact fields
`channel`, `protocol`, `kind`, `session`, `generation`, `revision`, `payload`. Send revisions
and view revisions have distinct ownership. Typed focus entry/exit and ping/pong carry no game
authority. This same-origin frame is an ownership boundary, not a security sandbox against
hostile child code.

## Lifecycle and rendering

A mount owns one input listener set, one scheduled RAF, one canvas and its texture/font resources.
Pixi uses async `Application.init`, `autoStart:false`, a private stopped ticker, and detached
Pixi DOM interaction listeners. The adapter alone schedules drawing and owns DOM input.
Replacing a mount first disposes its predecessor. Disposing revokes input capability before
local pointer/focus cleanup, aborts pending asset work, removes listeners/canvas, cancels RAF,
and releases all mount-owned Pixi textures, sources, image bitmaps and font faces. A late
initialization completion destroys its own resources without attaching.

Pointer coordinates map from CSS bounds to logical viewport units; keyboard inputs are finite
typed presenter events. Pointer cancellation, blur, visibility changes, modal opening, resize,
and disposal clear local drag ownership. Visibility and explicit suspend stop RAF; resume
does not override document visibility. DPI affects device pixels and asset density only.
Preferences are returned to Rust for motion. The adapter records audio preferences but **audio
playback is unsupported** because no sound fixture exists; it creates no AudioContext.

The backend consumes ordered sprite, rectangle, path, text and transform/clip/opacity scope
commands. Camera and inherited affine matrices compose before device mapping. Stroke widths
scale with local geometry. Clips are intersected logical viewport masks, independent of camera
and transforms; primitive alpha inherits opacity. The same verified 1x/2x atlas resources and
baseline font are used. Asset paths are stage-relative with no traversal, query or fragments;
fetches stay on the exact origin. Expected compressed size/SHA-256, PNG header dimensions,
axis and whole-pack pixel caps are checked before image decode/upload. Missing resources,
unsupported commands, asset failures and WebGL context loss surface structured errors rather
than silently skipping geometry. Context restoration requires remount.

## Evidence limits

`npm test` includes real Rust-generated fixture validation, hostile/stale boundaries, asset
integrity/PNG bounds, typed iframe messages, pending-init disposal, twenty mock cleanup cycles,
and an actual Pixi scene-geometry check for zoomed stroke width. Mock DOM/GPU initialization
proves those tested adapter transitions only; it is not browser runtime or process-memory evidence.
Run the browser harness for mount cycles, native Rust input, visible pixels, focus, motion,
resize/DPI and measurements, and retain exact target/configuration receipts.

`on_frame.input_to_next_draw_ms` means the next draw after a DOM input was observed. It does
not mean the authority acknowledged a command or that feedback was visible. Measure input to
the specific returned revision being rendered separately. Browser RAF intervals, adapter draw
time, wrapper round trips and native-authority interop are separate signals; none is a global
renderer performance ranking. Text metric/rasterization differences remain explicit even with
identical font bytes. Audio, networking, native/mobile embedding and production phase acceptance
are outside this tool's implemented scope.
